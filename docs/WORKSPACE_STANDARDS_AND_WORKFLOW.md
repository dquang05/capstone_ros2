## 2. ROS 2 Standardization & REP Compliance

Every developer contributing to this repository must adhere to the official ROS Enhancement Proposals (REPs):

### 2.1. Coordinate Frames & Spatial Standards (REP-103 & REP-105)
* **Coordinate Orientation:** Right-Hand Rule:
  * **X-axis:** Points **Forward** (direction of nominal robot travel).
  * **Y-axis:** Points **Left** (lateral axis).
  * **Z-axis:** Points **Up** (vertical axis against gravity).
* **Units of Measure:** Strictly SI units:
  * Linear distances: **meters ($m$)**.
  * Angles & angular rates: **radians ($rad$)** and **radians/sec ($rad/s$)**.
  * Mass: **kilograms ($kg$)**.
  * Velocity & Acceleration: **$m/s$** and **$m/s^2$**.
* **TF Tree Hierarchy (REP-105):**
  $$\text{map} \longrightarrow \text{odom} \longrightarrow \text{base\_footprint} \longrightarrow \text{base\_link} \longrightarrow [\text{sub-links}]$$
  * `map`: World-fixed frame (drift-free, discontinuous pose corrections from AMCL/SLAM).
  * `odom`: Odometry-fixed continuous frame (smooth, subject to slow unbounded drift).
  * `base_footprint`: 2D planar projection of the robot footprint onto the ground ($z=0$).
  * `base_link`: Center of motion located on the active drive axle.

### 2.2. Naming Conventions (REP-144)
* **Packages:** Lowercase with underscores, prefixed with `amr_` (e.g., `amr_description`, `amr_navigation`).
* **Topics & Services:** Lowercase with forward slashes (e.g., `/cmd_vel`, `/scan`, `/imu/data`, `/odometry/filtered`).
* **TF Frame IDs:** Lowercase with underscores (e.g., `base_link`, `laser_frame`, `imu_link`, `left_wheel_link`).
* **Launch Files:** Named as `<verb>_<subject>.launch.py` or `<subject>_bringup.launch.py`.

## 3. Build System & Environment Rules

### 3.1. Symlink-Install Rule (`--symlink-install`)
To maximize development velocity, all builds must utilize symbolic links. This links Python code, Xacro files, launch scripts, and YAML configurations directly from `src/` into `install/`.
* When `--symlink-install` is active: **Editing any Python script, launch file, or Xacro file takes effect immediately without rebuilding.**
* Only C++ modifications or adding new files to `data_files` in `setup.py` require running a build.

### 3.2. Sourcing Order in Shell
Every terminal session must follow this exact layering order:
1. **Underlay:** `source /opt/ros/jazzy/setup.bash`
2. **Overlay:** `source install/setup.bash` (inside `capstone_ros2/`)

### 3.3. Terminal Shortcuts (Bash Aliases)
The following aliases are configured in `~/.bashrc`:
* `cb`: Builds the workspace (`colcon build --symlink-install`).
* `cbp <package_name>`: Builds a single package (`colcon build --symlink-install --packages-select <pkg>`).
* `sdev`: Sources the current workspace (`source install/setup.bash`).
* `cdev`: Cleans build artifacts (`rm -rf build install log`).

## 4. Git & Version Control Standards

### 4.1. Tracked vs. Untracked Artifacts
* **Never commit to Git:**
  * `build/`, `install/`, `log/`
  * Python bytecode (`__pycache__/`, `*.pyc`)
  * SolidWorks native source assemblies (`.SLDASM`, `.SLDPRT`) exceeding 50MB (store in cloud storage or dedicated CAD release tags).
* **Always commit to Git:**
  * All source code in `src/`
  * Optimized visual meshes (`.stl`, `.dae`) inside `amr_description/meshes/`
  * Config files, world files, and documentation in `docs/`

### 4.2. Commit Message Convention (Conventional Commits)
Follow the standard format: `<type>(<scope>): <short description>`
* `feat(description)`: Add new robot link or sensor mount in Xacro.
* `feat(gazebo)`: Add Pizza 4P's dining tables to simulation world.
* `fix(localization)`: Correct covariance matrix in EKF config.
* `docs(readme)`: Update simulation setup instructions.
* `refactor(nav2)`: Tune DWB trajectory critic weights.

## 5. Coding & Modeling Best Practices

### 5.1. Robot Description (URDF / Xacro)
1. **Visual vs. Collision Separation:** Always use high-fidelity meshes for `<visual>` and simple geometric primitives (`<box>`, `<cylinder>`, `<sphere>`) for `<collision>`.
2. **Analytical Inertias:** Never leave `<inertial>` tags empty or with dummy zeros. Use analytical macros from `macros_inertia.xacro`.
3. **Caster Wheel Friction:** Passive caster collisions must have `mu1 = 0.0` and `mu2 = 0.0` to prevent rotational jamming.

### 5.2. Python Node Standards (`rclpy`)
1. **Object-Oriented Design:** All nodes must inherit from `rclpy.node.Node`.
2. **Lifecycle & Clean Shutdown:** Always enclose node spinning in `try ... finally` blocks and call `node.destroy_node()` and `rclpy.shutdown()`.
3. **Logging:** Never use raw Python `print()`. Always use `self.get_logger().info()`, `warn()`, or `error()`.
